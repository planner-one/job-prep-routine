# 취업 준비 루틴 보드

취업 준비 로드맵, 주간 계획, 데일리 실행, 누적 기록과 면접 연습을 함께 관리하는 정적 웹 앱입니다.

## 배포

연결 저장소 `planner-one/job-prep-routine`은 공개입니다. 배포 대상에는 2주 학습(`learning.html`)과 한 장 플랜(`learning-plan.html`)이 포함됩니다.

2주 학습의 Vercel 운영 주소는 `https://job-prep-routine.vercel.app/learning.html`입니다. 기존 정적 사이트 주소는 `https://planner-one.github.io/job-prep-routine/`입니다. `codex/job-prep-routine` 브랜치에 푸시하면 GitHub Actions가 GitHub Pages에 자동 배포합니다.

## 작업 시작 규칙

사용자가 질문하거나 계획을 물을 때는 설명과 확인만 제공합니다. 파일 수정, 문항 생성, 테스트 실행, 에이전트 작업 등 실제 구현은 사용자가 **“구현해”** 또는 **“시작해”**라고 명시적으로 요청한 경우에만 시작합니다.

## 로컬 실행

```sh
python3 -m http.server 8787 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8787/`을 엽니다. 오늘 허브에서 다음 일정과 면접 세션을 바로 이어갈 수 있습니다.

## 화면 구성

- `index.html`: 오늘 진척·다음 일정·면접 이어하기·주간 요약
- `roadmap.html`: 일정 운영 기준과 PDF 출력
- `weekly.html`: 주간 계획과 요일별 실행 흐름
- `learning.html`: 9월 4일~17일 자유로운 강의 선택·54개 강의와 정리노트·학습 기록·선택한 날짜의 복습
- `learning-plan.html`: 2주 학습 원칙·강의 우선순위·완료 기준을 담은 한 장 이미지
- `daily.html`: 오늘의 시간표·지원·면접·운동 기록
- `history.html`: 최근 7일·30일 실행 지표와 활동 이력
- `interview/`: 이력서 기반 면접 질문·답변 연습 대시보드

## 코드 구조

- `assets/site-shell.css`: 모든 화면이 공유하는 상단바·모바일 탭바
- `assets/routine.css`: 루틴 CSS의 고정 진입점. 실제 스타일은 `assets/styles/routine/`에서 공통 → 화면별 → 반응형 → 인쇄 순서로 관리
- `src/routine-data.js`, `src/routine-core.js`: 일정 원본과 날짜·저장·진척 공통 로직
- `src/*-plan-core.js`: DOM에 의존하지 않는 데일리·주간 계획 로직
- `src/learning-data.js`, `src/learning-core.js`, `src/learning-app.js`: 2주 학습 원본·전용 저장·화면 상호작용
- `src/*-app.js`: 각 HTML 화면의 렌더링과 이벤트 연결
- `src/legacy-learning.js`: 이전 학습 데이터 제거 규칙의 단일 기준
- `interview/assets/dashboard.css`: 면접 CSS의 고정 진입점. 실제 스타일은 `interview/assets/styles/dashboard/`에서 기존 기반 → Focus 덮어쓰기 순서로 관리
- `interview/assets/dashboard.js`: 설정 → 저장·세션 → URL → 렌더링 → 사용자 명령 → 초기화 순서의 면접 화면 진입점

CSS 진입점의 `@import` 순서는 기존 cascade를 보존하는 계약이므로 바꾸지 않습니다. 공개 HTML 경로와 브라우저 저장 키도 호환성을 위해 유지합니다.

## 저장 기준

루틴 상태는 오전 2시를 하루 경계로 계산해 이 브라우저의 `job-prep-routine:*` 키에 저장합니다. 화면 선택은 `job-prep-routine:preferences.v1`, 2주 학습은 `job-prep-routine:learning-sprint.v1`, 면접 진행은 `interview-prep.session.v1`에 따로 저장합니다. 루틴·면접 기록은 기기별이며, 2주 학습은 아래의 Vercel 연결 후 동기화합니다. 이전 데이터에 남아 있는 학습 주제와 `learning` 일정은 불러올 때 무시하며, 새 2주 학습 기록과 지원·면접·운동 기록은 유지합니다.

## 검증

```sh
npm run check
npm test
npm run export:roadmap-pdf
```

`npm run check`는 루틴 소스와 PDF 검증 스크립트만 문법 검사합니다. `npm test`는 루틴 단위·계약·브라우저 테스트를 실행합니다.

## 학습 대시보드 운영

학습 페이지는 왼쪽의 2주 학습 메뉴, 가운데 문서형 작업 영역, 오른쪽 강의 목록으로 시작합니다. 반영 현황·프로그램·복습·기록·학습 방법으로 전환해도 강의 목록은 계속 보입니다. 가운데 작업 영역만 전환하며 각 화면의 스크롤 위치를 유지합니다. 첫 상세 미리보기는 실제 수강 선택으로 처리하지 않습니다. 9월 4~17일 안에 학습할 강의와 순서·분량은 사용자가 정하며, 추천 분류는 참고 정보입니다. ‘내 선택’은 사용자가 체크한 강의만 포함합니다. 안 보기·추가 신청·수강 체크는 서로 독립적으로 보존합니다. 강의 상세의 삭제 버튼은 목록과 반영 현황에서만 강의를 제외하며, 체크·노트·기록·예약한 복습은 보존합니다. ‘삭제한 강의’ 필터에서 복원할 수 있습니다. ‘이번 추가’는 9월 6일 요청한 네 링크와 9월 11일 추가한 Docker Essentials를 모으며 기존 강의는 중복 생성하지 않습니다.

54개 강의의 공식 목차·개별 수업 시간·총시간·조회일·원문 URL은 `src/learning-curriculum.js`에 보존합니다. 영상과 자료·퀴즈를 구분하며, 목차 체크·들은 영상 개수·누적 시청 시간 중 현재 고른 방식 하나로 진도를 계산합니다. 목차마다 시청·정리·회고·적용을 독립적으로 체크하고, 간편 개수·시간 방식에서는 최근 공부 상태를 체크합니다.

강의 목록은 강의 성격(이론 중심·실습 중심·이론+실습)과 실습 유무를 따로 표시합니다. 공식 태그가 있으면 우선하고, 없으면 공개 소개·목차의 구성을 검토합니다. `learningFormat`에 확인일·판단 근거·공식 URL을 보존하며 상세에서 펼쳐 볼 수 있습니다. 코딩·도구 조작 외의 설계·말하기 과제는 비코딩 실습으로 구분합니다. 단순 퀴즈·사례 설명은 실습으로 계산하지 않고, 근거가 불충분하면 실습 없음 대신 실습 미확인으로 표시합니다. 분류는 사용자 체크·노트·우선순위 및 서버 동기화 데이터와 분리합니다.

반영 현황에는 내 선택 강의의 진도·체크·적용한 곳과 청년프로그램 일정이 모입니다. 프로그램은 있음·없음을 선택하고 날짜·시작·종료 시간만으로 추가합니다. 없음 선택은 기존 일정을 보관하되 현황에서 숨깁니다.

강의 상세 맨 위의 `강의 완료`는 사용자가 직접 체크·해제합니다. 완료는 목록과 반영 현황에도 표시하며, 영상 진도·수강 선택·목차 체크를 자동으로 바꾸지 않습니다. 새로고침·백업·기기 동기화·삭제 후 복원에도 보존합니다. 이전 버전의 탭이 완료 필드 없이 저장하더라도 서버는 이미 저장된 완료 표시를 유지합니다.

선택한 강의에서 이어 볼 위치와 기존 정리노트 링크를 관리합니다. 메모와 질문은 선택이며, 하루 기록 수나 날짜별 강의 순서를 강제하지 않습니다. 복습 날짜는 직접 선택하고, 내일·3일 뒤·7일 뒤는 편의 기능으로 제공합니다. 이전 날짜별 답변·복습·체크는 학습 기록에서 계속 확인합니다.

사용자 선호: 학습 화면에는 대형 제목, 짙은 배경의 큰 배너, 장식용 숫자 카드를 다시 추가하지 않습니다. 작은 제목과 목록·상세 영역을 사용합니다. 추천은 실제 사용자 선택으로 자동 전환하지 않습니다.

검증은 오른쪽 강의 선택 → 목차 또는 개수·시간 체크 → 반영 현황 → 프로그램 유무·일정 → 새로고침 복원과 기존 기록 보존을 확인합니다. 목차의 영상시간 합계가 공식 총시간과 일치하는지도 검사합니다. 기능 검사 통과와 사용자 화면의 만족도는 별개로 평가합니다.

학습 화면 초기화 검증: HTTP 200과 문법 검사는 강의 렌더링 성공을 증명하지 않습니다. 모듈 변경 시 앱·코어·강의 데이터·커리큘럼의 버전을 함께 갱신하고, 초기 로딩·실패 안내를 유지합니다. 사용자에게 빈 화면이 보고되면 같은 주소의 실제 탭에서 목록과 상세의 표시·강의 전환을 확인한 후 완료를 보고합니다.

강의 순서는 숫자 옆 이동 핸들을 누른 채 드래그하거나 핸들에 초점을 두고 위·아래 방향키로 바꿉니다. 전체 목록의 위쪽이 높은 우선순위이며, 검색·필터에서도 전체 순위 숫자를 유지합니다. 순서는 기존 학습 저장 키의 `courseOrder`에 저장합니다. 삭제한 강의의 위치는 보존하고 신규 강의는 기존 순서 뒤에 붙입니다.

선택 강의의 남은 시간은 오른쪽 목록 상단과 반영 현황에 표시합니다. ‘이번 2주에 선택’(`inPlan`)한 강의 중 완료하지 않은 강의의 공식 전체 영상시간을 초 단위로 합산해 시간·분으로 표시합니다. ‘강의 완료’를 체크하면 해당 시간이 빠지고 해제하면 다시 더해집니다. 완료된 강의도 선택 개수에는 포함합니다. 삭제한 강의는 제외하며, 검색·필터·우선순위·개별 시청 체크는 합계에 영향을 주지 않습니다. ‘안 볼 강의’와 ‘내 선택’을 동시에 체크한 경우 명시적인 선택을 보존해 합계에 포함합니다.


모바일(600px 이하)은 작은 제목·기간·동기화를 한 줄에 두고, 검색과 필터 선택을 같은 줄에 배치합니다. 공통 브랜드 상단바와 여러 줄 필터를 감춰 목록 위 높이를 줄이며 주요 이동은 하단 메뉴로 제공합니다. 강의 목록과 상세는 한 번에 하나씩 표시합니다. 상단의 `강의 목록`으로 돌아가면 검색·필터와 목록 스크롤 위치가 유지됩니다. 다른 학습 화면은 선택 메뉴로 열며, 목차 제목 아래 시청·정리·회고·적용을 각각 체크합니다. 데스크톱의 세 영역 배치는 유지합니다. 모바일 목록·상세의 세로 스크롤은 페이지로 전달하도록 허용하고 body의 세로 스크롤 잠금을 제거해 Android Chrome의 당겨서 새로고침을 막지 않습니다. 순서 이동 손잡이만 드래그를 처리합니다. Android Chrome의 네이티브 당기기 동작은 데스크톱의 모바일 폭 검사로 검증했다고 보고하지 않습니다.

`학습 기록 → 기록 옮기기 · 백업`에서 2주 학습 JSON 파일을 내보내거나 가져옵니다. 파일 선택 후 요약을 확인하고 `확인하고 반영`을 눌러야 교체됩니다. 가져오기 직전 원문은 기존 학습 저장 키 뒤의 `:before-import`에 한 번 보관하며, `가져오기 전 기록으로 복구`로 되돌립니다. 다른 루틴·면접 저장 키는 건드리지 않습니다. 개인 기록 파일은 공개 저장소나 배포 파일에 포함하지 않습니다. 이는 수동 이동 기능이며 자동 동기화가 아닙니다. 노트북의 실제 기록 이전과 UI 코드 배포 완료는 따로 보고합니다.


## Vercel · Neon 기기 동기화

Vercel Hobby와 Neon 무료 프로젝트를 연결하는 구성입니다. `api/learning.js`가 개인 인증과 저장 요청을 처리하고, `server/learning-store.js`가 Neon에 하나의 학습 상태와 버전을 보관합니다. Supabase 연결 코드는 제거했습니다. Vercel 프로젝트 생성·DB 연결·실제 기록 이전·기기 간 검증은 각각 별도 단계이며 코드 배포만으로 연결 완료라고 판단하지 않습니다.

Vercel의 Storage에서 Neon **Free**를 연결해 Production 환경에 `DATABASE_URL`을 추가합니다. Environment Variables에 32자 이상의 무작위 `LEARNING_ACCESS_CODE`를 Sensitive로 추가하고 재배포합니다. 개인 접속코드는 비밀번호 관리 도구에서 생성·보관합니다. 두 값은 서버 전용이며 Git·정적 파일·채팅 로그에 넣지 않습니다. 최초 인증된 접근에서 전용 테이블을 생성하므로 별도 SQL 편집은 필요하지 않습니다. 코드 변경 시 기존 세션은 무효화됩니다.

노트북과 모바일은 같은 Vercel 주소의 `기기 동기화`에서 같은 접속코드를 입력합니다. 코드는 저장하지 않고 HttpOnly·Secure·SameSite 세션 쿠키를 사용합니다. 인증하지 않은 조회·저장과 다른 사이트에서 보낸 변경 요청은 차단합니다. 서버 응답은 캐시하지 않습니다. 이 인증은 개인 학습 데이터 API에 적용되며 정적 페이지 자체를 숨기는 기능은 아닙니다.

처음 옮길 때에는 **실제 체크·삭제 기록이 남아 있는 노트북의 GitHub Pages 주소**에서 `학습 기록 → 기록 옮기기 · 백업`으로 파일을 내보냅니다. 새 Vercel 주소에서 해당 파일을 가져오고 요약을 확인한 뒤 반영합니다. 이어 `기기 동기화 → 이 노트북의 체크·삭제 기록으로 시작`으로 서버에 저장합니다. 새 모바일에서는 접속코드를 한 번 입력하면 서버 기록을 자동으로 불러옵니다. 연결 전 로컬 기록이 있으나 변경 기준이 없으면 `이 기기 기록과 서버 기록 합치기`로 체크·메모를 합치고 충돌 항목만 선택합니다. 기준 이력이 없는 과거 체크 해제는 추측하지 않으며 연결 후 직접 해제합니다. 서로 다른 주소의 브라우저 저장소는 자동으로 공유되지 않습니다. 기존 Pages 주소와 원문 기록은 유지합니다.

서버 행이 이미 있으면 초기 업로드로 덮어쓰지 않습니다. 연결·가져오기 직전 로컬 원문은 복구용으로 보관합니다. 이후 변경은 400ms 동안 모아 전송하고, 열린 화면에서 5초마다 변경 버전을 확인합니다. 변경이 없으면 자료 본문을 재전송하지 않으며 숨겨진 화면에서는 주기 확인을 멈춥니다. 다른 항목의 동시 변경은 합치고 같은 항목의 충돌은 사용자 선택 전까지 유지합니다. 오프라인 변경과 서버 기준값은 기기 캐시에 보존합니다. 최초 접속 실패도 5초 주기·온라인 복귀·화면 복귀 때 재연결합니다. 연결 전에 변경한 기록 역시 기준과 함께 저장하므로 첫 연결 전에 새로고침해도 보존합니다. 저장 원문이 없거나 손상되면 해당 기기의 전송 대기 사본을 먼저 복원하며 서버의 빈 기록으로 초기화하지 않습니다.

동기화 요약은 접힌 메뉴 제목에도 표시해 모바일 강의 목록에서 `서버 저장 완료`, `접속코드 입력`, `전송 대기`, `저장 실패`를 구분합니다. 로컬·GitHub Pages 주소는 `이 기기에만 저장`과 운영 주소를 표시합니다. 브라우저 저장 실패를 동기화 성공으로 가리지 않으며 백업 안내를 펼칩니다. 펼친 동기화 메뉴에서는 현재 접속 주소·화면 버전과 서버의 목록·선택·삭제 수를 표시해 기기 화면과 대조할 수 있습니다.

동기화 재발 검증은 엔진의 병합 검사 외에 실제 초기화 함수를 포함합니다. 새 기기 자동 연결, 최초 오프라인 후 재연결, 저장 사본 복구, 체크 해제 후 즉시 새로고침, 연결 전 변경을 검사합니다. `version` 또는 `courses`가 없는 이전 형식의 부분 기록도 인식하며, 이를 손상으로 오인해 오래된 사본으로 되돌리지 않습니다. 연결 전 최초 백업은 재연결 때 덮어쓰지 않습니다. 실제 사용한 모바일의 주소·브라우저·로그인 상태는 별도로 확인하며, 자동 검사만으로 해당 기기의 기록 복구를 완료했다고 보고하지 않습니다.

Vercel 빌드는 `npm run build:vercel`로 공개 화면·자산만 `_site/`에 구성합니다. 서버 코드와 환경 변수는 정적 출력에서 제외합니다. 기존 GitHub Actions는 계속 Pages를 갱신합니다. Vercel의 `test-m/job-prep-routine`은 `planner-one/job-prep-routine` 저장소 한 개에 연결되어 있으며, `codex/job-prep-routine` 브랜치를 Production으로 추적합니다. 이후 이 브랜치에 push하면 Vercel도 운영 배포를 시작합니다. 실제 배포 성공은 Vercel의 Ready 상태와 운영 응답으로 별도 확인합니다.

연결 도구의 파일 업로드 한도는 4MB입니다. 이 경로로 배포할 때는 큰 플랜 PNG만 업로드에서 제외하며, 빌드 스크립트가 고정 Git 커밋의 공개 원본을 가져와 SHA-256 일치 후 배포물에 넣습니다. 원본 이미지와 Git 파일은 변경하지 않습니다. 일반 Git·CLI 배포에서는 포함된 로컬 이미지를 그대로 복사합니다.
