# 운영 로드맵·데일리 포커스 역할 분리 설계

## 배경

운영 로드맵과 데일리 포커스가 같은 날짜, 운영 모드, 시간표, 학습 조합을 각각 저장해 하루 실행 체크가 중복되고 있다. 운영 로드맵은 반복해서 체크하는 화면이 아니라 일상 운영 기준을 확인하는 참고 문서로 남기고, 하루의 실제 실행과 기록은 데일리 포커스 한 곳에서 처리한다.

## 확정한 역할

- 운영 로드맵: 읽기 전용 일정 기준표와 다운로드 가능한 PDF
- 주간 실행 보드: 요일별 운영 계획과 주간 진척 확인
- 데일리 포커스: 오늘의 시간표, 지원 파이프라인, 학습 조합, 하루 마감 실행 기록
- 기록·분석: 데일리와 주간 기록을 날짜별로 모아 7일·30일 추이 확인

사용 흐름은 `운영 기준 참고 → 주간 계획 → 데일리 실행 → 기록·분석`으로 고정한다.

## 운영 로드맵

### 읽기 전용 웹 기준표

- 운동일, 비운동일, 러닝일, 핵심 유지일 일정을 모두 한 페이지에 제공한다.
- 러닝일은 21시 시작과 22시 시작의 차이를 함께 표시한다.
- 기존 세 가지 운영 원칙과 각 시간표의 시간·활동·카테고리를 유지한다.
- 회사 지원, 면접, 학습, 식사, 운동의 하루 흐름을 참고하는 용도로만 사용한다.
- 일정 체크박스, 학습 선택 체크박스, 현재 날짜, 초기화 버튼을 제거한다.
- 운영 로드맵용 `localStorage`를 새로 읽거나 저장하지 않는다.
- 화면 상단에 홈 이동, 데일리 포커스 이동, PDF 다운로드를 제공한다.

### PDF

- 실제 PDF 파일을 `output/pdf/취업준비-운영-로드맵.pdf`에 생성한다.
- 웹 기준표의 PDF 다운로드 링크도 같은 파일을 가리킨다.
- PDF에는 운영 원칙과 모든 운영 모드의 전체 시간표를 빠짐없이 담는다.
- 여러 페이지 사용을 허용하며 모드 단위로 페이지가 자연스럽게 분리되게 한다.
- 링크나 웹 조작 요소는 PDF에 포함하지 않는다.

## 데일리 포커스 통합

### 유지하는 기능

- 운동일·비운동일·러닝일·핵심 유지일 선택
- 러닝 시작 시각 21시·22시 선택
- 현재 모드의 시간표 체크
- 회사 4곳의 플랫폼, 공고 링크, 분석·자소서·지원 단계
- Spring, Redis, Java, 프로젝트 적용, CS, 코딩테스트 복수 선택
- 오늘 구현한 것, 막힌 것, 내일 첫 행동 작성
- 오전 2시 날짜 경계, 자동 저장, PDF 미리보기

### 로드맵에서 가져오는 기능

- 시간표 위에 `전체`, `운동·회복`, `취업·면접`, `개발 학습`, `식사·휴식` 카테고리 필터를 추가한다.
- 카테고리 필터는 표시 범위만 바꾸며 체크 상태나 진척 계산에는 영향을 주지 않는다.
- 필터 선택은 일시적인 화면 상태로 취급하고 저장하지 않는다.
- 로드맵의 세 운영 원칙은 데일리 상단의 기존 핵심 세 가지 문구와 합쳐 중복 카드 없이 유지한다.

## 기록과 기존 데이터

- 데일리 저장 형식 `job-prep-routine:daily:YYYY-MM-DD`는 변경하지 않는다.
- 주간 저장 형식도 변경하지 않는다.
- 기존 `job-prep-routine:roadmap:*` 기록은 삭제하지 않는다.
- 기록·분석 페이지는 과거 로드맵 기록을 계속 읽어 기존 기록을 보존한다.
- 읽기 전용 로드맵 전환 이후에는 새로운 로드맵 날짜 기록이 만들어지지 않는다.
- 완료율의 기본 소스 우선순위는 기존과 같이 데일리, 과거 로드맵, 주간 순서로 유지한다.

## 홈 화면

- 운영 로드맵 카드는 `읽기 전용 일정 기준표·PDF`임을 설명한다.
- 데일리 포커스 카드는 `오늘의 유일한 실행 기록 화면`임을 설명한다.
- 네 개의 진입점은 유지하되 역할이 겹쳐 보이지 않도록 문구를 수정한다.

## 예외와 안전성

- 현재 선택한 카테고리에 해당하는 일정이 없으면 빈 화면 대신 안내 문구를 표시한다.
- 모드를 바꾸거나 필터를 전환해도 다른 모드에서 저장된 기존 체크는 훼손하지 않는다.
- 읽기 전용 로드맵은 잘못된 저장 상태의 영향을 받지 않는다.
- PDF 생성이 실패하더라도 웹 기준표 자체는 계속 읽을 수 있게 독립시킨다.

## 검증 기준

- 데일리 카테고리 필터가 일정 표시만 바꾸고 저장값·진척률을 바꾸지 않는다.
- 데일리의 기존 모드, 러닝 시각, 지원 파이프라인, 학습, 메모 저장·복원이 그대로 동작한다.
- 운영 로드맵 HTML에 체크박스, 날짜 초기화, 로드맵 상태 저장 코드가 없다.
- 운영 로드맵에서 모든 모드와 러닝 시각의 전체 일정이 확인된다.
- 기존 로드맵 기록은 기록·분석에서 계속 나타난다.
- 생성된 PDF의 페이지 수, 텍스트, 여백, 잘림, 한글 렌더링을 확인한다.
- 전체 자동 테스트와 문법 검사를 통과한다.

## 이번 범위에서 제외

- 로그인, Firebase, GitHub Actions, 외부 배포
- 기존 로드맵 기록 자동 삭제 또는 데일리 기록으로 변환
- 운영 로드맵에서 데일리 모드를 자동 설정하는 버튼
- 카테고리 필터 선택 상태의 영구 저장
