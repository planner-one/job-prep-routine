# 운영 로드맵 카테고리 선택·PDF 페이지 완성도 개선 설계

## 배경

현재 운영 로드맵 웹페이지는 운동일, 비운동일, 러닝 21시, 러닝 22시, 핵심 유지일의 다섯 시간표를 모두 펼친다. 참고하려는 일정 하나를 찾으려면 긴 화면을 스크롤해야 하므로 카테고리 선택형 기준표라는 목적에 맞지 않는다.

현재 PDF도 첫 장에만 핵심 운영 원칙 카드가 있고 이후 장은 일정표부터 시작한다. 각 장이 독립적으로 완성된 운영 기준표처럼 보이도록 페이지 구성을 통일해야 한다.

## 목표

- 웹에서는 선택한 운영 카테고리의 시간표 하나만 보여준다.
- 러닝일에서만 21시와 22시 시작 시간을 추가로 선택한다.
- PDF는 정확히 5페이지를 유지하며 모든 페이지를 같은 완성형 레이아웃으로 만든다.
- 읽기 전용 로드맵이라는 역할과 기존 PDF 안전 검증을 유지한다.

## 웹 운영 로드맵

### 카테고리 선택

- 시간표 위에 `운동일`, `비운동일`, `러닝일`, `유지일` 네 개의 선택 버튼을 둔다.
- 최초 진입 시 `운동일`을 선택한다.
- 선택한 카테고리에 대응하는 시간표 하나만 화면에 노출한다.
- `러닝일`을 선택했을 때만 `21시 시작`, `22시 시작` 보조 선택 버튼을 표시한다.
- 러닝일의 최초 시작 시각은 21시로 한다.
- 다른 카테고리의 시간표는 화면에서 숨겨 긴 스크롤이 생기지 않게 한다.
- 선택 상태는 화면에서만 사용하며 `localStorage`에 저장하지 않는다.

### 표현과 접근성

- 카테고리 버튼은 하나만 선택되는 탭 형태로 표현한다.
- 선택 버튼에는 `aria-selected`, 연결된 시간표에는 탭 패널 역할과 접근 가능한 이름을 제공한다.
- 키보드와 포인터 입력 모두 같은 선택 동작을 사용한다.
- 기존 핵심 운영 원칙 카드 3개, 홈·데일리 이동, PDF 다운로드를 유지한다.
- 체크박스, 날짜, 저장, 초기화 기능은 추가하지 않는다.

## PDF 구성

PDF는 다음 순서의 A4 세로 5페이지로 고정한다.

1. 운동일
2. 비운동일
3. 러닝일 · 21시 시작
4. 러닝일 · 22시 시작
5. 핵심 유지일

각 페이지는 다음 요소를 같은 순서와 여백으로 가진다.

1. `취업 준비 운영 로드맵` 문서 표제
2. 해당 일정 유형의 제목과 짧은 설명
3. `지원은 하루 3~4개`, `면접 언어를 매일 다듬기`, `학습은 결과물로 남기기` 핵심 원칙 카드 3개
4. 해당 유형의 오전·오후·저녁·밤 전체 일정표

웹 전용 선택 버튼과 이동 링크는 PDF에서 숨긴다. 화면에서 숨겨진 네 개의 시간표는 인쇄 시 모두 복원한다. 첫 페이지에만 존재하던 공통 헤더와 원칙 영역은 인쇄에서 제외하고, 각 시간표 페이지 안의 인쇄 전용 표제와 원칙 카드를 사용해 중복을 막는다.

카드와 일정표의 간격·행 높이를 인쇄 전용으로 조정해 각 일정 유형이 한 페이지 안에 들어가게 한다. 단, 글자를 지나치게 줄이거나 행을 다음 페이지로 분할하지 않는다.

## 구조와 데이터 흐름

- `getRoadmapVariants()`가 제공하는 기존 다섯 일정 데이터와 순서는 변경하지 않는다.
- 웹 카테고리 선택은 다섯 패널의 표시 상태만 바꾼다.
- 러닝일 선택과 시작 시각 선택을 합쳐 `running-21` 또는 `running-22` 패널 하나를 표시한다.
- 인쇄 스타일은 화면 선택 상태와 관계없이 다섯 패널을 모두 노출한다.
- 운영 로드맵은 기존과 같이 저장소를 읽거나 쓰지 않는다.
- 과거 로드맵 기록을 읽는 기록·분석 기능은 변경하지 않는다.

## 검증 기준

- 최초 화면에는 운동일 시간표만 보인다.
- 네 카테고리를 전환하면 대응 시간표 하나만 보인다.
- 러닝일에서 21시와 22시 전환이 해당 시간표를 정확히 바꾼다.
- 선택 과정에서 새로운 로드맵 `localStorage` 값이 만들어지지 않는다.
- PDF 선택 버튼은 인쇄되지 않고 다섯 일정은 모두 인쇄된다.
- 실제 PDF는 A4 정확히 5페이지이며 페이지별로 표제, 해당 일정 유형, 핵심 원칙 3개, 대응 일정 전체를 포함한다.
- 전체 72개 일정과 기존 PDF 원본 일치·원자 교체 검증을 유지한다.
- 실행 패키지와 8787 로컬 화면을 같은 파일로 동기화한다.

- 로그인, Firebase, GitHub Actions, 외부 배포
- 기존 기록 형식 변경 또는 삭제
