# 백엔드 면접 템플릿 카탈로그·오늘의 큐 설계

## 1. 목적

기존 취업 준비 루틴 보드에 백엔드 면접 질문 전용 학습 공간을 추가한다. 사용자는 152개 질문을 카테고리·검색·학습 상태로 탐색하고, 각 질문의 개인 답변과 복습 기록을 남길 수 있다. 목록 중심의 학습형 카탈로그를 주 기능으로 두고, 자동 추천과 직접 조정을 결합한 `오늘의 면접 큐`를 보조 기능으로 제공한다.

이 기능은 기존 데일리·주간·로드맵·기록 완료율과 분리된 독립 학습 도구다. 로그인·데이터베이스·외부 배포 없이 현재 브라우저의 `localStorage`에 저장한다.

## 2. 콘텐츠 범위와 출처

- 대상은 `maeil-mail/maeil-mail-contents` 저장소의 백엔드 질문 152개다.
- 카테고리는 원본 목차의 8개 분류와 순서를 유지한다.
- 앱에 포함하는 원본 정보는 질문 ID, 질문 제목, 카테고리, 원본 순서, GitHub 원문 URL뿐이다.
- 원문의 답변 본문, 이미지, HTML, 참고 자료 전문은 복제하지 않는다.
- 각 상세 화면에서 원본 GitHub 문서를 새 탭으로 여는 출처 링크를 제공한다.
- 프론트엔드 질문은 이 기능에 포함하지 않는다.

정적 질문 데이터는 빌드 과정 없이 브라우저 모듈에서 읽을 수 있는 형태로 저장한다. 질문 ID는 원본 파일 ID인 `be-N`을 그대로 사용하고, 상세 주소는 `template.html?id=be-N`으로 고정한다.

## 3. 화면 구조

### 3.1 홈

기존 네 개 보드 아래에 다섯 번째 `백엔드 면접 학습` 진입 카드를 전체 너비로 추가한다. 기존 네 보드의 역할과 순서는 바꾸지 않는다. 새 카드는 다음 정보를 짧게 보여준다.

- 백엔드 152문항
- 카테고리 탐색과 개인 답변 기록
- 오늘의 면접 큐 5문항

### 3.2 목록 페이지: `templates.html`

목록 페이지는 다음 순서로 구성한다.

1. 홈 이동과 페이지 제목
2. 전체 진척 요약
   - 전체 문항
   - 학습 중
   - 복습 필요
   - 완료
3. 오늘의 면접 큐
   - 논리 날짜와 `오늘 N / 5 완료`
   - 질문 5개
   - 각 질문의 카테고리, 상태, 상세 이동
   - `고정`, `다른 문항으로 교체`, `오늘 완료`
4. 카탈로그 도구
   - 제목 검색
   - 8개 카테고리와 `전체`
   - 상태 필터: 전체, 미학습, 학습 중, 복습 필요, 완료
   - 즐겨찾기만 보기
5. 질문 목록
   - 원본 순서의 세로 목록
   - 질문 번호, 제목, 카테고리, 상태, 자신감, 즐겨찾기
   - 오늘의 큐에 직접 추가
   - 필터 결과 수와 빈 결과 안내

검색과 필터는 동시에 적용한다. 검색은 앞뒤 공백을 제거하고 대소문자를 구분하지 않는다. 질문 목록 자체에는 체크박스를 두지 않으며, 상세 기록과 오늘의 큐 완료만 실제 학습 상태를 변경한다.

### 3.3 상세 페이지: `template.html?id=be-N`

하나의 재사용 가능한 상세 페이지가 쿼리 ID에 맞는 질문을 렌더링한다. 152개의 물리적 HTML 파일을 만들지 않지만 각 문항은 고유 URL로 직접 열 수 있다.

상세 페이지는 다음을 제공한다.

- 목록으로 돌아가기
- 질문 번호, 제목, 카테고리
- 학습 상태 선택
- 자신감 1~5 선택
- 즐겨찾기와 오늘의 큐 고정
- 개인 답변
- 핵심 키워드
- 추가 메모
- 마지막 학습일
- 오늘 완료
- 원본 GitHub 링크
- 이전·다음 문항
- 현재 문항 PDF 미리보기

입력은 변경 즉시 저장한다. 저장 완료 상태는 `aria-live` 영역으로 알린다. 이전·다음 문항은 현재 카탈로그 필터와 무관하게 원본 순서를 따른다.

유효하지 않거나 존재하지 않는 `id`는 빈 편집 화면을 만들지 않는다. `질문을 찾을 수 없습니다` 안내와 목록 이동 버튼을 표시한다.

## 4. 질문 상태 모델

전체 저장 스키마는 버전 필드를 가진다. 질문별 상태는 다음 의미를 갖는다.

```js
{
  status: 'unseen' | 'studying' | 'review' | 'done',
  favorite: boolean,
  queuePinned: boolean,
  confidence: 0 | 1 | 2 | 3 | 4 | 5,
  answer: string,
  keywords: string,
  memo: string,
  lastStudiedAt: string | null,
  updatedAt: string | null
}
```

- 기본 상태는 `미학습`, 자신감은 미선택을 뜻하는 0이다.
- `오늘 완료`는 해당 날짜 큐의 완료와 `lastStudiedAt`을 갱신한다.
- `오늘 완료`가 전역 상태를 임의로 `완료`로 바꾸지는 않는다. 전역 상태는 사용자가 직접 선택한다.
- 질문별 초기화는 현재 질문의 상태만 기본값으로 돌린다. 실행 전에 확인을 받는다.
- 전체 기록 삭제 UI는 제공하지 않는다.

저장 키는 기존 보드와 충돌하지 않는 별도 네임스페이스를 사용한다.

```text
job-prep-routine:interview:state
job-prep-routine:interview:queue:YYYY-MM-DD
```

상태 저장값이 손상되거나 잘못된 타입을 포함하면 유효한 필드만 정규화하고 나머지는 기본값으로 복구한다. 다른 질문과 기존 루틴 보드의 저장값은 변경하지 않는다.

## 5. 오늘의 면접 큐

### 5.1 논리 날짜

기존 루틴 보드와 동일하게 오전 2시를 하루 경계로 사용한다. 날짜별 큐는 처음 목록 또는 상세 페이지를 열 때 생성하고 그 논리 날짜가 끝날 때까지 고정한다. 새로고침과 페이지 이동으로 큐가 재선정되지 않는다.

### 5.2 추천 우선순위

중복 없이 최대 5문항을 다음 순서로 채운다.

1. 사용자가 `오늘의 큐 고정`으로 지정한 문항
2. 상태가 `복습 필요`이거나 자신감이 1~2인 문항
3. 상태가 `미학습`인 문항
4. 마지막 학습일이 가장 오래된 문항
5. 같은 조건이면 원본 질문 순서

큐 고정 문항은 최대 5개다. 여섯 번째 고정을 시도하면 기존 고정을 해제해야 한다는 안내를 보여준다. 유효한 후보가 5개보다 적으면 실제 후보 수만 표시한다.

### 5.3 직접 조정

- `다른 문항으로 교체`는 고정되지 않았고 오늘 완료하지 않은 현재 문항 하나만 다음 추천 후보로 바꾼다.
- 교체 후보는 현재 큐에 이미 있는 ID를 제외한다.
- 사용자는 카탈로그에서 원하는 질문을 오늘의 큐에 직접 넣을 수 있다.
- 큐가 5개면 고정되지 않았고 완료하지 않은 마지막 항목을 교체한다.
- 고정 또는 완료 항목만 남아 자동 교체가 불가능하면 이유를 안내하고 큐를 바꾸지 않는다.
- 오늘 완료를 취소할 수 있으며 큐 구성은 그대로 유지한다.

날짜별 큐 저장값은 다음 정보를 가진다.

```js
{
  date: 'YYYY-MM-DD',
  ids: ['be-1', 'be-2'],
  completedIds: ['be-1'],
  updatedAt: string
}
```

과거 큐 키는 삭제하지 않는다. 이번 기능에서는 과거 큐 분석 화면을 만들지 않지만 이후 확장을 위한 원본 기록으로 보존한다.

## 6. 모듈 경계

구현은 책임을 다음처럼 분리한다.

- `src/interview-data.js`
  - 152개 질문과 8개 카테고리의 정적 원본 메타데이터
- `src/interview-core.js`
  - 상태 정규화, 검색·필터, 통계, 큐 추천·고정·교체·완료, 저장 키 계산
  - DOM과 `localStorage`에 직접 의존하지 않는 순수 함수
- `src/templates-app.js`
  - 목록 페이지 렌더링과 사용자 이벤트, 저장·복원
- `src/template-detail-app.js`
  - 상세 페이지 렌더링, 자동 저장, 이전·다음 이동, 인쇄

기존 `logicalDateString()`을 재사용해 오전 2시 경계를 통일한다. 목록과 상세 앱은 같은 core 정규화 함수를 사용해 서로 다른 저장 해석을 만들지 않는다.

## 7. 반응형·접근성·인쇄

- 기존 `assets/routine.css`의 색상, 글꼴, 카드, 포커스 링을 재사용한다.
- 데스크톱에서는 오늘의 큐를 5개 카드 흐름으로, 모바일에서는 한 열 목록으로 표시한다.
- 질문 카탈로그는 항상 세로 목록이며 가로 스크롤에 의존하지 않는다.
- 모든 입력에는 연결된 label 또는 명확한 accessible name을 제공한다.
- 필터와 즐겨찾기 토글은 `aria-pressed`를 사용한다.
- 검색 결과 수, 저장 상태, 큐 변경 결과는 `aria-live`로 알린다.
- 키보드만으로 검색, 필터, 큐 조정, 상세 작성, 이전·다음 이동이 가능해야 한다.
- 외부 GitHub 링크는 새 탭에서 열고 `noopener`를 사용한다.

상세 인쇄는 현재 문항 한 개만 남긴다. 질문, 개인 답변, 핵심 키워드, 메모, 상태, 자신감, 원본 출처는 인쇄하고 검색·큐 조작·저장 안내·초기화 버튼은 숨긴다. 입력 컨트롤 대신 현재 값을 읽기 전용 텍스트로 인쇄한다.

## 8. 오류와 비손실 규칙

- 정적 질문 데이터의 ID 중복, 누락된 제목, 잘못된 카테고리, 원본 URL 누락은 테스트 실패로 취급한다.
- 손상된 `localStorage` JSON은 페이지를 중단시키지 않고 기본값으로 연다.
- 질문 하나를 저장할 때 다른 질문 상태와 날짜별 큐를 보존한다.
- 필터 결과가 없으면 기존 목록을 제거하고 명시적 빈 결과 안내를 보여준다.
- 교체 후보가 없으면 현재 큐를 유지하고 이유를 알린다.
- 저장 공간 오류가 발생하면 사용자가 작성 중인 DOM 값을 지우지 않고 저장 실패를 알린다.
- 원본 GitHub 페이지가 외부에서 없어져도 개인 기록과 목록 렌더링은 유지한다.

## 9. 검증 기준

### 데이터·코어 테스트

- 질문 152개, 고유 ID 152개, 카테고리 8개
- 모든 질문의 제목·카테고리·원본 URL·원본 순서
- 검색, 카테고리, 상태, 즐겨찾기 복합 필터
- 상태 정규화와 다른 질문의 비손실 보존
- 오전 2시 전후 날짜별 큐 키
- 추천 우선순위와 동률 원본 순서
- 고정 최대 5개, 중복 제거, 교체, 직접 추가, 완료·취소
- 손상된 상태·큐 저장값 복구

### 계약·브라우저 테스트

- 홈의 다섯 번째 진입 카드
- 목록 페이지의 요약·큐·필터·질문 목록
- 상세 페이지의 고유 URL, 자동 저장, 이전·다음, 잘못된 ID 안내
- 새로고침 뒤 필터·상태·답변·큐 복원
- 논리 날짜가 바뀌기 전 큐 고정과 오전 2시 이후 새 큐 생성
- 키보드 포커스와 동적 상태 알림
- 상세 인쇄에서 조작 숨김과 입력값의 읽기 전용 출력
- 기존 루틴 보드 저장값·완료율·canonical PDF가 변경되지 않음

## 10. 범위 제외

- 원문 답변 본문 복제
- 프론트엔드 질문
- 로그인, 계정별 동기화, 데이터베이스
- 외부 API를 통한 실시간 GitHub 동기화
- 기존 데일리·주간 완료율과의 통합
- 과거 면접 큐 분석 페이지
- 배포 및 호스팅 변경
