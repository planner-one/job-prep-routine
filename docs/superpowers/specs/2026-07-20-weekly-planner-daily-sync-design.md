# 주간 일정 플래너·데일리 실행 연동 설계

## 배경

현재 주간 실행 보드는 요일별 체크리스트와 고정 시간표를 함께 제공하지만, 같은 실행 항목을 데일리 포커스에서도 다시 체크해야 한다. 또한 주간 시간표는 운영 유형에 따라 완전히 고정되어 있어 그날 할 일을 고르거나 우선순위에 맞게 옮길 수 없다.

주간 실행 보드는 `이번 주에 무엇을 언제 할지 정하는 계획 화면`, 데일리 포커스는 `오늘 실제로 수행하고 체크하는 실행 화면`으로 역할을 분리한다. 주간에서 만든 일정은 해당 날짜의 데일리에 자동으로 연결하며, 주간에서는 데일리 실행 결과만 읽기 전용으로 보여준다.

## 목표

- 주간의 중복 체크리스트와 보조 고정 시간표를 하나의 세로 일정 플래너로 합친다.
- 기본 일정 선택과 사용자 일정 추가를 지원한다.
- 식사와 취침은 운영 유형별 고정 시간으로 유지하고, 나머지 일정은 재배치할 수 있게 한다.
- 순서 변경 시 시간을 자동 계산하며, 정확한 수정이 필요할 때만 시간 편집 모드를 연다.
- 수용할 수 없는 일정은 겹치거나 축소하지 않고 미배치 상태로 남긴다.
- 주간 계획을 데일리에 자동 반영하고 실제 완료 입력은 데일리 한 곳에서만 받는다.
- 기존 데일리·주간·기록 데이터를 삭제하거나 계획으로 잘못 집계하지 않는다.

## 검토한 방식과 선택

### 선택: 고정 앵커 기반 세로 일정표

식사와 취침을 고정 앵커로 두고, 선택한 일정 카드를 그 사이에 세로로 배치한다. 카드 순서를 바꾸면 각 일정의 소요시간을 유지한 채 시간이 다시 계산된다. 사용 빈도가 높은 순서 변경은 바로 할 수 있고, 정밀한 시간 수정은 별도 모드로 감춰 평소 화면을 단순하게 유지할 수 있다.

### 검토했으나 선택하지 않은 방식

- 시간 슬롯 캘린더: 원하는 시각에 직접 놓기는 쉽지만 작은 화면에서 드래그가 어렵고 빈 시간대 때문에 세로 길이가 지나치게 길어진다.
- 완전 자유 시간표: 모든 항목의 시작·종료 시각을 항상 편집할 수 있지만 반복 입력이 많고, 사용자가 불편해했던 복잡한 시간 입력 화면이 다시 생긴다.

## 역할과 사용자 흐름

사용 흐름은 다음과 같이 고정한다.

1. 주간 실행 보드에서 요일과 운영 유형을 선택한다.
2. 기본 목록 또는 직접 추가로 할 일을 고른다.
3. 세로 목록에서 순서를 조정하고 필요한 경우에만 시간을 편집한다.
4. 해당 날짜의 데일리 포커스가 주간 계획을 불러온다.
5. 실제 일정 완료, 지원 파이프라인, 메모는 데일리에서 입력한다.
6. 주간 실행 보드와 기록·분석은 데일리 결과를 읽어 진척을 보여준다.

주간 계획 자체는 완료나 생산성 활동으로 계산하지 않는다.

## 주간 실행 보드 화면

### 상단 진척

- 지원, 숙지·면접, 운동, 학습 카드는 유지한다.
- 수치는 현재 주에 저장된 일곱 날짜의 데일리 실행 기록만 집계한다.
- 지원 수치는 데일리 지원 파이프라인의 실제 `지원` 완료를 기준으로 한다.
- 운동·러닝·면접·학습은 데일리에서 완료한 계획 항목의 종류를 기준으로 집계한다.
- 다른 탭에서 데일리를 체크한 경우 주간 화면이 다시 활성화되거나 `storage` 이벤트를 받으면 수치를 갱신한다.

### 요일과 운영 유형

- 월요일부터 일요일까지의 기존 요일 탭을 유지한다.
- 운동일, 비운동일, 러닝일, 핵심 유지일 구분과 러닝 21시·22시 선택을 유지한다.
- 새 주를 처음 열면 기존 운영 로드맵의 해당 유형 일정으로 각 요일 계획을 채운다. 사용자는 식사·취침을 제외한 행을 삭제하거나 다시 추가할 수 있다.
- 운영 유형을 바꾸면 해당 유형의 식사·취침 앵커와 기본 활동을 적용한다.
- 유형에 종속된 운동·러닝·샤워·귀가 기본 활동만 새 유형에 맞게 교체한다. 사용자가 선택한 취업·학습 일정과 직접 추가 일정은 보존하고 다시 배치한다.
- 운영 유형 변경으로 공간이 부족해진 항목은 미배치 일정으로 보낸다.

### 하나로 합친 세로 일정표

기존의 체크리스트 열과 고정 시간표 열을 제거하고 선택 요일 안에 한 개의 세로 목록만 둔다.

일반 행은 다음 요소를 가진다.

- 드래그 손잡이
- `09:30–10:00` 형태의 한 덩어리 시간 표기
- 일정 이름과 카테고리
- 데일리 실행 전에는 `예정`, 실행 후에는 읽기 전용 완료 상태
- 키보드와 터치 환경을 위한 위·아래 이동 버튼

식사와 취침 행은 `고정` 배지를 표시하고 이동 버튼을 제공하지 않는다. 일정 이름은 약 16~17px, 시간은 약 14~15px로 하여 현재 목록보다 크게 보이게 한다.

선택 요일 제목 영역 오른쪽에는 `일정 추가`와 `시간 편집`을 둔다. 평상시에는 시간 입력 칸을 노출하지 않는다.

### 일정 추가

`일정 추가`는 카테고리별 기본 목록과 직접 추가 영역을 연다.

기본 목록은 다음 항목을 포함한다.

- 취업·면접: 일정·공고 확인, 공고 분석, 자소서 조정·지원, 이력서·포트폴리오 숙지, 면접 연습·복기
- 개발 학습: Spring, Redis, Java, CS, 코딩테스트, 프로젝트 적용
- 운동·회복: 아침 운동, 저녁 러닝, 샤워·정리, 가벼운 마무리·내일 준비

학습 주제는 하나 또는 여러 개를 골라 한 개의 학습 블록으로 묶을 수 있다. 예를 들어 Spring만 선택하거나 `Spring · Redis` 조합을 한 행으로 추가할 수 있다. 같은 기본 일정은 한 요일에 한 번만 추가하며, 반복이 필요하면 직접 추가 일정을 사용한다.

기본 일정은 현재 운영 로드맵의 소요시간을 기본값으로 사용한다. 직접 추가 일정은 이름, 카테고리, 소요시간을 입력해야 추가할 수 있다.

### 순서 변경과 자동 시간 계산

- 드래그 손잡이 또는 위·아래 버튼으로 일반 일정을 옮긴다.
- 식사·취침 앵커끼리의 순서는 바뀌지 않지만, 일반 일정은 앵커의 앞이나 뒤로 이동할 수 있다.
- 이동이 끝나면 해당 구간의 시작부터 목록 순서대로 소요시간을 배정한다.
- 먼저 놓인 일정에 우선권을 주며, 다음 고정 앵커 전까지 완전히 들어가지 못한 일정은 `미배치 일정`으로 이동한다.
- 시간을 맞추기 위해 일정 길이를 자동 축소하거나 서로 겹치게 하지 않는다.
- 순서를 다시 바꾸면 사용자가 정밀 편집했던 시간도 새 순서를 기준으로 재계산하며, 짧은 안내를 표시한다.

### 시간 편집

- 오른쪽 위 `시간 편집`을 누른 경우에만 편집 모드가 열린다.
- 평소 목록의 시간은 `09:30–10:00`처럼 한 덩어리로만 표시한다. 물결표, 오전·오후가 반복되는 여러 입력 상자를 목록에 늘어놓지 않는다.
- 편집 모드에서 행의 시간 범위를 누르면 작은 편집 영역에서 시작과 종료를 수정한다.
- `저장`과 `취소`를 제공하고, 저장 후에는 다시 단순한 시간 표기로 돌아간다.
- 식사·취침 시간은 읽기 전용이다.
- 다른 일정이나 고정 앵커와 겹치거나 종료가 시작보다 빠르면 저장하지 않고 해당 행 가까이에 오류를 표시한다.

### 운영 유형별 고정 앵커

아침·점심·저녁·취침을 고정한다. 점심은 모든 유형에서 `13:00–14:00`으로 유지한다.

- 운동일: `07:30–08:50` 아침, `13:00–14:00` 점심, `18:50–19:50` 저녁, `23:00–24:00` 취침
- 비운동일: `07:10–08:20` 아침, `13:00–14:00` 점심, `18:50–19:50` 저녁, `23:00–24:00` 취침
- 러닝일: `07:10–08:20` 아침, `13:00–14:00` 점심, `18:50–19:50` 저녁, 21시 러닝일은 `23:00–24:00` 취침, 22시 러닝일은 `24:00` 취침
- 핵심 유지일: `08:10–09:00` 아침, `13:00–14:00` 점심, `18:00–19:00` 저녁, `23:00` 취침

식후 20분은 각 식사 앵커의 라벨과 소요시간에 포함한다.

자동 배치의 하루 시작 경계는 운동일 `05:40`, 비운동일·러닝일 `07:00`, 핵심 유지일 `08:00`으로 한다. 마지막 배치 경계는 각 유형의 취침 시작 시각이다.

### 미배치 일정

- 시간 안에 들어가지 않는 일정은 목록 하단의 `미배치 일정`에 원래 순서대로 남긴다.
- 상단에 미배치 개수와 `시간이 부족해 배치되지 않은 일정이 있습니다` 경고를 표시한다.
- 사용자는 우선순위를 바꾸거나 소요시간·정확한 시간을 수정하거나 일정을 삭제해 해결한다.
- 미배치 일정은 주간 계획에는 저장하지만 데일리 실행 목록에는 넣지 않는다.

## 데일리 포커스 연동

### 계획 불러오기

- 데일리 날짜로 주간 월요일 키와 요일을 계산해 대응하는 주간 계획을 찾는다.
- 주간 계획이 있으면 모드, 러닝 시작 시각, 배치된 일정 순서와 시간을 그대로 렌더링한다.
- 데일리의 운영 유형 선택과 학습 조합 선택은 계획 편집 기능으로 사용하지 않는다. 현재 유형과 학습 조합을 읽기 전용으로 보여주고 `주간 계획 수정` 링크를 제공한다.
- 아직 저장된 주간 계획이 없는 날은 해당 요일의 기본 운영 유형 일정으로 안전하게 대체한다.
- 지원 회사명·플랫폼·링크·분석·자소서·지원, 메모 입력은 기존처럼 데일리에 남긴다.

### 실행 스냅샷과 변경

- 데일리에 첫 실제 입력이 생기기 전까지는 최신 주간 계획을 자동으로 불러온다.
- 첫 일정 체크, 지원 파이프라인 변경 또는 메모 입력 시 그날의 일정 이름·시간·카테고리·안정적인 항목 ID를 데일리 실행 스냅샷으로 저장한다.
- 스냅샷이 만들어진 뒤 주간 계획이 바뀌면 오늘의 실행 기록을 조용히 덮어쓰지 않는다. 데일리에 변경 안내와 `변경 계획 반영` 동작을 제공한다.
- 변경 계획을 반영할 때 같은 항목 ID의 체크는 유지하고 새 항목은 미완료로 추가한다. 이미 완료한 뒤 주간에서 삭제된 항목은 `이전 계획에서 완료` 기록으로 보존한다.
- 재정렬과 시간 수정은 항목 ID를 바꾸지 않으므로 기존 체크가 유지된다.
- 데일리 입력은 기존처럼 즉시 저장한다. 오전 2시 논리 날짜 경계가 지나면 이전 날짜 키의 스냅샷은 그대로 기록으로 남고 새 논리 날짜를 연다.

### 주간의 읽기 전용 실행 상태

- 주간 일정 행은 해당 날짜의 데일리 스냅샷과 체크 상태를 읽는다.
- 주간 화면에서는 완료 체크박스를 제공하지 않는다.
- 계획과 데일리 스냅샷의 버전이 다르면 `계획 변경 대기` 상태를 표시한다.
- 미래 날짜는 `예정`, 데일리 입력이 없는 지난 날짜는 `기록 없음`으로 구분한다.

## 시간과 데이터 모델

### 시간 모델

- 내부 시간은 화면 문자열이 아니라 자정부터의 분 단위 정수로 저장·계산한다.
- `24:00`은 1440분으로 허용한다.
- 표시할 때만 `HH:MM` 또는 `HH:MM–HH:MM` 문자열로 변환한다.
- `20:30 이후` 같은 표현은 계획 계산에 사용하지 않고 명확한 시작 시각과 하루 종료 경계를 사용한다.

### 주간 저장

기존 키 `job-prep-routine:weekly:<월요일 날짜>`를 유지하되 스키마 버전을 추가한다.

각 요일은 다음 정보를 갖는다.

- 운영 유형과 러닝 시작 시각
- 계획 버전
- 배치된 일정: 항목 ID, 기본 일정 ID 또는 사용자 일정 표시, 이름, 카테고리, 소요시간, 시작·종료 시각, 순서
- 미배치 일정: 같은 항목 정보와 미배치 사유
- 기존 방식의 주간 체크 데이터가 있으면 기록 호환용 레거시 완료 데이터

식사·취침 앵커는 운영 유형 데이터에서 파생하며 중복 저장하지 않는다.

### 데일리 저장

기존 키 `job-prep-routine:daily:<논리 날짜>`를 유지한다. 기존 필드와 함께 다음 정보를 정규화해 저장한다.

- 참조한 주간 키·요일·계획 버전
- 실행 일정 스냅샷
- 완료 후 계획에서 제거된 보존 항목

기존 `checkedIds`, 지원 회사, 학습 데이터, 메모는 손실 없이 유지한다.

## 기존 데이터 호환

- 기존 주간 상태는 처음 읽을 때 새 스키마로 비손실 정규화한다.
- 기존 모드와 러닝 시각을 이용해 기본 계획을 만들고, 과거 `applications`, `tasks`, `learningTopics`, `maintenance` 체크는 레거시 완료 데이터로 따로 보존한다.
- 새 주간 화면은 레거시 체크를 수정하지 않는다.
- 기록·분석은 데일리가 없는 과거 날짜에 한해서 기존 주간 체크를 완료율 대체 자료로 계속 사용할 수 있다.
- 새 주간 계획만 저장한 날짜는 활동, 완료, 생산성 그래프로 집계하지 않는다.
- `현재 주 초기화`는 새 계획만 기본값으로 되돌리고 보존된 레거시 완료 기록은 삭제하지 않는다.
- 잘못된 저장값은 가능한 필드만 복구하고 기본 계획을 사용하되 원본 키를 자동 삭제하지 않는다.

## 모듈 경계

DOM과 저장소 부작용이 없는 공용 계획 코어를 둔다. 이 코어는 다음 역할만 담당한다.

- 주간 키와 요일 해석
- 새·기존 주간 데이터 정규화와 마이그레이션
- 고정 앵커 생성
- 순서 변경, 분 단위 시간 재계산, 충돌 검사, 미배치 판정
- 날짜별 데일리 일정 해석과 스냅샷 병합
- 데일리 실행 기록만 사용하는 주간 진척 요약

주간 화면은 계획 편집과 읽기 전용 완료 표시, 데일리 화면은 실행 체크와 스냅샷 저장, 기록 코어는 과거 데이터 요약만 담당한다. 주간이나 데일리 화면 모듈을 서로 직접 불러오지 않는다.

## 접근성·인쇄

- 드래그만 강요하지 않고 위·아래 이동 버튼과 키보드 조작을 제공한다.
- 이동 후 새 위치와 시간 또는 미배치 결과를 접근 가능한 상태 메시지로 알린다.
- 시간 편집 오류는 해당 입력과 연결하고 포커스를 유지한다.
- 고정 행, 예정, 완료, 기록 없음, 계획 변경 대기는 색만으로 구분하지 않는다.
- 기존 `PDF 미리보기`를 유지한다. 인쇄 시 편집 버튼, 드래그 손잡이, 미배치 조작 버튼은 숨기고 선택 요일의 계획과 읽기 전용 주간 진척을 인쇄한다.

## 검증 기준

### 계획 코어

- 오전 2시 논리 날짜, 월요일 키, 월·연말 경계를 정확히 계산한다.
- 운영 유형과 러닝 21시·22시에 맞는 식사·취침 앵커를 만든다.
- 순서 변경 후 일정이 겹치지 않고 소요시간이 유지된다.
- `24:00` 경계와 고정 앵커를 넘는 항목은 미배치된다.
- 직접 추가 항목 ID는 새로고침과 재정렬 뒤에도 유지된다.
- 잘못된 시간 편집은 저장되지 않는다.

### 주간·데일리 연동

- 주간 계획이 정확한 날짜의 데일리에 반영된다.
- 첫 실행 전 주간 변경은 자동 반영되고, 첫 실행 후 변경은 사용자 확인 없이 스냅샷을 덮어쓰지 않는다.
- 계획 변경을 반영해도 같은 항목의 완료 체크와 삭제된 완료 기록이 보존된다.
- 계획 편집은 데일리 키, 지원 파이프라인, 메모를 변경하지 않는다.
- 주간의 완료 표시와 상단 진척은 데일리 실행 기록만 사용한다.
- 계획만 저장한 날의 완료율과 생산성은 증가하지 않는다.

### 호환성과 화면

- 기존 주간 fixture를 새로 저장한 뒤에도 레거시 체크가 남는다.
- 기록의 데일리, 과거 로드맵, 레거시 주간 완료율 우선순위를 유지한다.
- 일정 추가, 학습 조합, 직접 추가, 드래그, 위·아래 이동, 시간 저장·취소, 미배치 경고가 새로고침 후 복원된다.
- 실제 브라우저에서 다른 탭의 데일리 체크가 주간의 읽기 전용 상태에 반영된다.
- 시간은 평상시에 한 범위로 보이고 목록 전체에 복잡한 시간 입력 상자가 노출되지 않는다.
- 전체 자동 테스트, 문법 검사, 실행 패키지 동기화를 통과한다.

## 이번 범위에서 제외

- 로그인, Firebase, GitHub Actions, 외부 배포
- 여러 기기나 브라우저 사이의 동기화
- 데이터베이스 도입
- 주간 화면에서 실행 완료를 직접 체크하는 기능
- 시간 슬롯형 달력 또는 자유 크기 조절 캘린더
- 과거 레거시 기록의 자동 삭제
